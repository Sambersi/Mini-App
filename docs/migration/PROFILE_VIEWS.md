# Чтение рефералов, топов и статистики

2026-11-27, stage03-runtime. Добавлены 23 функции прежнего контракта и getTopPlayersByTotalBalance для реального обработчика `топ`/`форбс`/`рейтинг`. Его прямой SQL к users заменён вызовом нового репозитория; открытие SQLite в bot.js остаётся для других ещё не перенесённых обработчиков и будет удалено после их замены.

Выборки читают нормализованные players, wallets, inventory_balances, player_preferences, player_donation_state и player_referrals. Исторические недействительные ссылки (13) спроецированы в player_referral_intents, поэтому чтению профиля больше не нужен разбор migration_issues. Исходные вопросы и архив сохраняются. Список, счётчик рефералов и сезонный отбор используют значения обеих таблиц; сервер не создаёт FK-связь с несуществующим пригласившим.

Миграция 014 добавляет players.legacy_rowid. Импорт сохраняет исходный SQLite rowid, новое создание присваивает следующий номер под тем же mutex, что numeric_id. getAllUsers и выборки с равными значениями сохраняют исходный порядок вместо произвольной сортировки по Telegram ID. Сезонный топ требует отдельного порядка при равенстве: исходный SQLite GROUP BY + DESC выдаёт ID в убывающем порядке; общий реферальный топ — в возрастающем. Это обнаружено реальной сверкой, воспроизведено на синтетическом SQLite и явно сохранено в SQL MariaDB. Дата сезонного отсечения 2025-06-23 не изменена.

Новые функции сохраняют формы ответа, ограничения количества строк, нулевое отображение отсутствующих сумм там, где оно было в исходном коде, и NULL в полном профиле. Техническая информация о балансе складывает PF через BigInt и возвращает строку при выходе за безопасный диапазон Number. SUM и сложение в MySQL используют DECIMAL там, где сумма нескольких BIGINT может переполниться.

assertInactiveProjection останавливает повторную проекцию до перезаписи предметных таблиц, если имеются новые runtime-игроки, проводки, операции, платежи, завершения регистрации или инвентарный журнал. Недостаточно только выключить runtime_active, чтобы разрешить перезапись уже использованной базы.

Проверки на MariaDB 10.5: 39 сравнений со снимком SQLite, включая полные результаты топов PF/карты/DF/NPF/контейнеров/урона/донатов/рефералов, список карт и статистику NPF; для трёх игроков — списки и счётчики рефералов, числовой ID, признак скрытия и остатки. Все совпали, включая порядок строк. Отдельно 1489 полных профилей / 101252 поля и порядок getAllUsers совпали. Локально 101 node:test прошёл; SQL-проверки регистрации и защиты импорта — 19, прежние денежные/сессионные/Stars/скины — 34. Сравнение выборок не является Telegram-прогоном.

Ограничения: полный runtime ещё не подключён; новый фасад db.js, остальные прямые SQLite-вызовы и финансовые обработчики остаются в работе. getPlayerBalanceInfoByNumericId дополнительно проверен локально на больших суммах и NULL; его данные входят в полную сверку профилей, но сама административная команда в Telegram не запускалась.
