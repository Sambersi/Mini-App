## Публикация и окружение

- Разработка изолирована в stage03-runtime; хост по-прежнему отслеживает master. Ветка на хосте не менялась. Подтверждён работающий релиз 5b0db166eaa9, activeStorage=sqlite.
- Обнаружено: Windows использует локальный системный прокси, прямые Node/Git не работали. Разовая команда git с `-c http.proxy=<GetSystemWebProxy().GetProxy(github).AbsoluteUri>` восстановила push, без изменения глобальных настроек. master 5b0db16 и feature до 739f883 отправлены. Приватный адрес прокси и helper находятся только в temp/host-control.
- Доступ к панели восстановлен через системный прокси. Приватный bootstrap use-system-proxy.cjs задаёт proxy agent только процессам управления; глобальные настройки не менялись. Пользователь также подтвердил загрузку панели.
- Проверки feature исполняются в /temp/migration-lab на хосте: загружаются файлы с проверкой SHA, временный startup hook запускает тесты и сам восстанавливает оригинальный startupChecks.js в finally. Рабочие Telegram-операции остаются в master/SQLite. Оригинал startupChecks SHA-256: 48e72634b66f8d0036cf7301949a91c06da4981862a45ccbb88609f2a9fc2aec.

## Сделано в feature

- 991 обнаруженный прямой вызов модулей БД ожидает результат. Сохранены последовательные асинхронные операции массивов; старт бота ждёт восстановления состояния. Это не означает перенос всех raw SQL и динамических вызовов.
- API-аутентификация, владелец данных и роли журналов, передача initData в plain/React готовы в коде; React собран, dist включён в Git. Дефект оформления Mini App по указанию пользователя отложен.
- Новый контракт: 311 функций и 2 константы. Сейчас подключено 77 функций, 234 ещё отсутствуют. Обе константы пока не подключены. Readiness блокирует DB_BACKEND=mysql и не допускает частичного fallback на SQLite.
- Добавлены catalog/chat/game-record repositories, state writes с whitelist и lock игрока. Общий state setter запрещает финансовые поля. Сохранены возвращаемые значения, порядок магазина «в наличии сначала» и исходная обработка имени. Dice reset исправляет связь через dice_rounds: в dice_bets нет chat_id. Листовые saveBet/saveDiceBet ещё не являются целой операцией приёма ставки со списанием.
- balanceAdjustment готовит идемпотентные изменения кошелька; skinPurchase делает списание/выдачу/серийный номер/stock одним commit. Проверка владения теперь до списания; старый код мог списать за уже имеющийся скин. Дебет с уже превышенного лимита не уничтожает превышение.
- Stars-сервис по уникальному charge делает DF, бонус рефереру, историю и статистику одним commit; старый Telegram-обработчик ещё не заменён. Миграции 001–012 применены на stage и checks.
- Префиксы/оружие/история донатов/формы сохраняются в нормализованных коллекциях с исходными JSON-токенами и порядком; назначение ролей сохраняет порядок/тип. Непривязанные ссылки и некорректный JSON не обнуляются молча. Отсутствующий кошелёк в чтении профиля отражается как NULL, а не выдуманный нулевой баланс.

## Проверки и ограничения

- Локально 93 node:test прошли. React build ранее прошёл. Секреты проверять перед очередным push.
- На реальной MariaDB прошли 34 сценария: 10 кошельков, 9 финансовых правил, 7 сессий, 4 Stars, 4 покупки скина. Повторы и конкуренция по 20 запросов, SQL-ошибка после списания с rollback; фикстуры очищены. Реальные Telegram-платежи и кнопки этим не проверены.
- Нативный импорт: 43 таблицы / 388061 строка; число строк и канонические SHA сверены. Полное чтение профиля: 1489 игроков / 101252 поля. Повторный прогон дополнительно сверил все 1489 профилей через пакетный getAllUsers. Выборки коллекций выполняются пакетами по 200 игроков, без отдельной транзакции на каждого игрока; локальный тест 401 игрока подтвердил 16 запросов в одной транзакции.
- Подготовлена защита капчи регистрации: единый формат всех ответов с nonce, проверка текущей сессии, запрет принятия политики до капчи. Сохранён переход для старой уже решённой капчи; ветка ещё не включена для Telegram. Атомарное завершение регистрации с наградами — следующий пакет.
- Кнопки покупки скина пока используют индекс каталога, который меняется после stock. До подключения сервиса нужны стабильный ID/серверная котировка и безопасный отказ старой неоднозначной кнопки. Не списывать за другой элемент страницы.
- Три callback-дубля различаются и не удалены. Удалён только идентичный второй card; маршрутизация Telegraf с имитацией обработчиков проверена, настоящий Telegram-прогон ожидается.
