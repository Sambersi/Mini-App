3. Продолжать SQL/права/конкуренцию на `_checks` по каждому новому сервису; обновлять журнал команд/кнопок и фактические результаты. Последний лабораторный прогон успешно сверил 60 SQL-сценариев, 39 сравнений выборок и полные профили, включая пакетное чтение и исходный порядок.

   Для платежей дополнительно нужна граница обработанных Telegram updates и сверка незавершённых оплат: старый обработчик не сохранял charge ID. Перенос истории сумм сам по себе не доказывает дедупликацию старого повторно доставленного платежа; новые события защищены inbox/telegram_payments.
