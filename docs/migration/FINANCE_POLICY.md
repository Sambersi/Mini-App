# Подготовка финансовых правил в этапе 3

Этап 3 выполняется до конца без остановки на подтверждение технических пакетов, по последнему указанию пользователя. Команды ещё не переключены. Новый слой: player_cards, player_bans, role_catalog, player_roles; деньги остаются только в wallets.

## Связи и правила

Входы `пополнить`, `снять`, `перевод`/`передать`/`перевести` зарегистрированы в bot.js. Пополнение и снятие также вызываются через topup_all/withdraw_all после инструкций карты. Карта → manage_card → show_topup_instruction / show_withdraw_instruction. Перевод ищет получателя по ответу или числовому ID; старый поиск по номеру карты недостижим из-за более ранней проверки всех цифр и отсутствующего импорта getUserByCardNumber — исправить при переводе адаптера.

Новый createCardFinance не принимает клиентский флаг администратора. Главный администратор берётся из серверной конфигурации; техническая роль читается через role_catalog/player_roles. Учитываются карты, баны в секундах, флаг блокировки переводов обоих игроков, is_blocked получателя и индивидуальный потолок отправителя. Исключения по ID извлекаются из существующих констант bankTransfers.js при импорте, без второго списка персональных ID. На повтор события возвращается сохранённый результат без новой проводки.

Проверки прав и лимитов находятся в той же транзакции, что оба остатка и журнал. Сумма `всё` вычисляется под блокировкой. Уведомления отправляются будущими адаптерами после commit. BigInt не округляется при разборе сумм с `к`.

## Явные исправления ошибок, влияющих на деньги

1. Снятие раньше сравнивалось с лимитом main 250/251/252/253M, а updateMainBalance обрезал результат до 140/175/185/200M. Новый сервис использует фактический лимит записи и уменьшает одинаково списание и зачисление. Средства больше не исчезают на разнице лимитов.
2. Перевод администратора обходил предварительный лимит карты получателя, но updateCardBalance всё равно обрезал зачисление. Новый сервис переводит одинаковую сумму в пределах фактической вместимости карты; остаток остаётся отправителю.
3. Списание с карты, уже превышающей лимит, больше не обрезает весь её остаток до лимита. Ограничение применяется к зачисляемой сумме получателя.

Экономические числа лимитов сохраняются из фактических функций записи. Старые превышающие лимит остатки не исправляются импортом. Отдельные card_level/account_level и tickets/fortune_tickets не объединяются.

## Проверки

Локально на момент пакета прошли 44 теста. На хосте 132fd33a1a69 все 19 интеграционных проверок прошли в отдельной `_checks`: пополнение, повтор, граница снятия, потолок отправителя, исключение администратора, запрет перевода заблокированному администратору, постоянный/истёкший бан получателя и отсутствие карты. Карточные записи всех 1489 игроков, 27 банов, 10 ролей и 102 назначения ролей сверены со снимком, вопросов ссылок 0. Оба флага импорта/проверок после прогона выключены.

MYSQL_FINANCE_IMPORT по умолчанию false. При включении переносит реквизиты, уровни, флаги, роли и баны из того же проверенного неизменяемого снимка этапа 2, сверяет каждое значение. Не переключает runtime и не изменяет кошельки. Непривязанные ссылки сохраняются в migration_issues; исходный архив остаётся неизменным.
